# 节点自适应宽高 / 内联编辑改造方案

> 目标：从「估算 + 多源同步」转向「DOM 真实测量 + 单源同步」，一次性解决之前 review 列出的 8 个 bug，并向 simple-mind-map 学习其架构经验。

---

## 现状回顾（问题汇总）

| 来源 | 问题 |
|---|---|
| stylesheet.ts | 1 级节点 height 用全局 `296` 算行数，与真实 `text-max-width` 不一致 → 文本截断 |
| stylesheet.ts | `*1.15` 魔数补偿测量误差，长文本被裁、短文本被拉宽 |
| renderPipeline.ts `measureNodeLabel` | `lineHeight: 18` 与 20px 实际字号 (line-height 1.35 ≈ 27px) 不匹配 |
| inlineEditor.ts `autoGrow` | `+24` 魔数 / 首帧 `contentH=0` fallback 偏小 → 闪烁 |
| inlineEditor.ts | width 永远卡在 280，不能 grow |
| 全局 | manualWidth/Height 一旦写入无法恢复自动 |
| 全局 | width / text-max-width / height 三次独立 canvas 测量，无缓存 |
| 全局 | 占位符与文本节点编辑器是两份独立实现（~400 × 2 行） |

---

## 关键认知：两条渲染路径要分开看

| 渲染路径 | 谁画的字 | 该用什么测量 |
|---|---|---|
| Cytoscape canvas 文字 (`text-opacity > 0`) | Cytoscape 内部 canvas | **canvas measureText**（保持） |
| HTML overlay（`hasMarkdownOverlay`，markdown 渲染） | DOM `<div>` | **离屏 DOM `<span>`**（新增） |

simple-mind-map 走 SVG → bbox()，普通文本走 SVG.text，富文本走离屏 div，**两条路径分别测量**。我们也应如此，不能强求一个测量函数适配两个渲染层。

## Phase 1 — 紧急 bug 修复（1 个 PR，~半天）

只动数学公式，不改架构，先把视觉错误堵住。

### 1.1 stylesheet.ts 1 级节点改用真实 wrapWidth

```ts
// stylesheet.ts:255-291 重构成单一计算函数
function computeFirstLevelMetrics(label: string, fontSize: number) {
    const PADDING_X = 44, PADDING_Y = 22;
    const LINE_HEIGHT = Math.ceil(fontSize * 1.4); // 24*1.4 ≈ 34（之前是 28，偏小）
    const MAX_WIDTH = 340;
    const BASE_WIDTH = 118;
    const SAFETY_PX = 4; // 加性余量替代 *1.15

    const lines = String(label).split('\n');
    const lineWidths = lines.map(l =>
        deps.measureTextWidthCanvas(l || ' ', fontSize, 'bold')
    );
    const longestW = Math.max(...lineWidths);

    const nodeWidth = Math.max(
        BASE_WIDTH,
        Math.min(MAX_WIDTH, Math.ceil(longestW) + SAFETY_PX + PADDING_X)
    );
    const wrapWidth = nodeWidth - PADDING_X;

    // ⚠️ 关键修复：用真实 wrapWidth 算行数
    const wrappedLines = lineWidths.reduce((sum, lw) =>
        sum + Math.max(1, Math.ceil(lw / wrapWidth)), 0
    );
    const nodeHeight = Math.max(54, wrappedLines * LINE_HEIGHT + PADDING_Y);

    return { nodeWidth, wrapWidth, nodeHeight };
}

// width/text-max-width/height 都从这里取，避免重复测量
'width': (ele) => readManualOrCompute(ele, 'width',
    label => computeFirstLevelMetrics(label, fontSize).nodeWidth),
'text-max-width': (ele) =>
    computeFirstLevelMetrics(ele.data('label'), fontSize).wrapWidth,
'height': (ele) => readManualOrCompute(ele, 'height',
    label => computeFirstLevelMetrics(label, fontSize).nodeHeight),
```

## Phase 2 — 离屏 DOM 测量替代 canvas（1 个 PR，~1 天）

### 2.1 新增 `domTextMeasurer.ts`

学习 simple-mind-map 的 `measureRichtextNodeTextSizeEl`：把测量元素挂在 cy 容器内继承 CSS。

```ts
// src/renderer/domTextMeasurer.ts
export class DomTextMeasurer {
    private host: HTMLDivElement;
    private cache = new Map<string, { width: number; height: number; lineCount: number }>();
    private cacheKeys: string[] = []; // LRU

    constructor(parent: HTMLElement) {
        this.host = document.createElement('div');
        this.host.className = 'zk-measure-host';
        this.host.style.cssText = `
            position: absolute;
            left: -99999px;
            top: 0;
            visibility: hidden;
            pointer-events: none;
            white-space: pre-wrap;
            word-break: break-word;
            overflow-wrap: anywhere;
        `;
        parent.appendChild(this.host);
    }

    measure(text: string, opts: {
        fontSize: number;
        fontWeight?: string;
        maxWidth: number;     // 用于换行
        lineHeight?: number;
    }): { width: number; height: number; lineCount: number } {
        const key = `${text}|${opts.fontSize}|${opts.fontWeight ?? 'n'}|${opts.maxWidth}|${opts.lineHeight ?? ''}`;
        const cached = this.cache.get(key);
        if (cached) return cached;

        this.host.style.fontSize = `${opts.fontSize}px`;
        this.host.style.fontWeight = opts.fontWeight ?? '500';
        this.host.style.lineHeight = `${opts.lineHeight ?? Math.ceil(opts.fontSize * 1.4)}px`;
        this.host.style.maxWidth = `${opts.maxWidth}px`;
        this.host.style.fontFamily = 'var(--font-text)';
        this.host.textContent = text;
        const rect = this.host.getBoundingClientRect();
        const result = {
            width: rect.width,
            height: rect.height,
            lineCount: Math.round(rect.height / (opts.lineHeight ?? opts.fontSize * 1.4))
        };

        if (this.cacheKeys.length >= 200) {
            const old = this.cacheKeys.shift()!;
            this.cache.delete(old);
        }
        this.cache.set(key, result);
        this.cacheKeys.push(key);
        return result;
    }

    invalidate() { this.cache.clear(); this.cacheKeys = []; }
    destroy() { this.host.remove(); this.cache.clear(); }
}
```

### 2.2 通过 deps 注入 stylesheet

```ts
// CytoscapeRenderer 构造里
this.domMeasurer = new DomTextMeasurer(this.container);
// 主题/字号变化时调用 this.domMeasurer.invalidate()

// stylesheet deps 多一项
domMeasure: (text, opts) => this.domMeasurer.measure(text, opts)
```

### 2.3 干掉 `*1.15` 和 `Math.ceil(lw/wrapWidth)` 估算

```ts
// stylesheet.ts 文本节点（HTML overlay 路径）
'width': (ele) => {
    if (manual) return manual;
    const m = deps.domMeasure(label, { fontSize: 20, maxWidth: 280 });
    return Math.max(BASE, m.width + PADDING_X);
},
'height': (ele) => {
    if (manual) return manual;
    const m = deps.domMeasure(label, { fontSize: 20, maxWidth: 280 });
    return Math.max(MIN_H, m.height + PADDING_Y);
},
```

### 2.4 区分两条路径

| 节点 | 测量方式 |
|---|---|
| `isTextOnly && hasMarkdownOverlay` | DOM 测量（`domMeasure`） |
| `isTextOnly && !hasMarkdownOverlay` | DOM 测量（plain text 也走它） |
| 文件/链接节点（canvas 渲染） | 保留 `measureTextWidthCanvas` |
| 1 级节点 | 由当前是哪种渲染决定，建议先保 canvas，等 Phase 3 改 |
| 根节点 | 保留 `measureNodeLabel` |

**风险**：DOM 测量首次调用会触发 layout reflow，~0.1ms 级别，加缓存后 hit rate 应 > 95%。在 `cy.style().update()` 高频调用时缓存是关键。

## Phase 3 — 编辑器交出尺寸控制权（1 个 PR，~1.5 天）

### 现状架构

```
用户输入 → onChange → autoGrow()
                    ├─ 自己测 contentH
                    ├─ Math.max(...) 计算
                    ├─ node.style({width, height}) 写回
                    └─ syncOverlayPos() 自己定位
```

**问题**：自适应公式 = stylesheet 一份 + autoGrow 一份，永远会走偏。

### 目标架构（学 simple-mind-map）

```
用户输入 → onChange → node.data('label', value)
                    └─ cy.style().update()       ← 触发 stylesheet 重算
                              ↓
                    （Cytoscape 重新布局节点）
                              ↓
                    cy.on('render') → syncOverlayPos()  ← 编辑器只读 bbox 跟位置
```

### 3.1 编辑器只更新 label，不再 `node.style({width, height})`

```ts
// inlineEditor.ts startPlaceholderInPlaceEdit autoGrow 改造
const autoGrow = () => {
    if (!this.cy || node.removed()) return;
    const value = mdEditor?.getValue() ?? '';
    // 只更新 label，让 stylesheet 算尺寸
    node.data('label', value);
    // overlay 位置在下一帧 render 后同步（已有的 syncOverlayPos 逻辑触发）
};
```

文本节点 inline edit 同样改：`resizeLiveEditNodeHeight` 这个 200 多行的函数**整个删掉**，编辑器不再自己估算高度。

### 3.2 syncOverlayPos 监听真实 render 事件

```ts
// 替换原来的 cy.on('zoom pan', syncOverlayPos)
const onRender = () => requestAnimationFrame(syncOverlayPos);
this.cy.on('render zoom pan', onRender);

const syncOverlayPos = () => {
    if (!this.cy || node.removed()) return;
    const bb = node.renderedBoundingBox({ includeLabels: false, includeOverlays: false });
    overlayEl.style.left = `${bb.x1}px`;
    overlayEl.style.top = `${bb.y1}px`;
    overlayEl.style.width = `${bb.w}px`;
    overlayEl.style.height = `${bb.h}px`;
    overlayEl.style.fontSize = `${20 * this.cy.zoom()}px`;
};
```

### 3.3 占位符编辑器最小尺寸的特殊处理

占位符**输入空内容时**仍要保持 `defaultW × defaultH` 让用户看见编辑框；这通过 stylesheet 的 baseWidth/minHeight 兜底已经满足，不需要 autoGrow 单独处理。

### 3.4 编辑结束时的 nodeSize 取值

```ts
// saveEdit 不再自己算 finalHeight，直接读 node.height()
const finalWidth = Number(node.width());
const finalHeight = Number(node.height());
```

**风险**：`cy.on('render')` 会在每次重绘时触发，频率高。要用 `requestAnimationFrame` 节流（已写）。Cytoscape 的 style fn 也会因为 `node.data('label', ...)` 触发——确认 `cy.style().update()` 会刷该节点。

## Phase 4 — UX 缺口补齐（1 个 PR，~半天）

### 4.1 节点右键菜单加「恢复自动尺寸」

```ts
// 在节点右键菜单逻辑里
{
    label: t('Reset to auto size'),
    visible: ele.data('isTextOnly') && (ele.data('manualWidthModel') || ele.data('manualHeightModel')),
    action: async () => {
        await mocHandler.modifyMOCData(file, (data) => {
            // 清掉持久化的 manual 尺寸
            const meta = data.metadata.ext;
            delete meta.node_text_sizes?.[ele.id()];
        });
        ele.removeData('manualWidthModel manualHeightModel');
    }
}
```

### 4.2 label 变化时自动放宽 manualHeight（可选）

```ts
// stylesheet height fn
'height': (ele) => {
    const manual = Number(ele.data('manualHeightModel') || 0);
    const auto = computeAutoHeight(ele);
    if (manual <= 0) return auto;
    // manual 高度小于自适应需要的最小高度时,自动放宽到 auto
    return Math.max(manual, auto);
},
```

这样 label 变长时不会被 manual 锁定截断，但用户拖大的高度仍保留。这一点 simple-mind-map 没做（他们走"显式恢复"路径），可看作我们的增强。

### 4.3 占位符复用文本节点编辑器（可选，最大改动）

当前 `startPlaceholderInPlaceEdit` 和 `startInPlaceTextEdit`（live edit 版本）几乎是两份镜像代码（~400 行 × 2）。Phase 3 抽掉 autoGrow 后差异就只剩：

- 占位符：保存时根据内容路由（wiki link / 文本 / 嵌入）
- 文本节点：保存时只更新 label

可以抽出共同的 `createInlineEditor(node, { onSave, onCancel, initialValue })`，两个调用点各自传 onSave 实现路由 / 普通保存。代码减少约 350 行。

## 落地顺序与验证策略

```
Phase 1 (bug 修复)  ──> 视觉验收：长 CJK / 多行 / 短文本 三组样本
   │
   ↓
Phase 2 (DOM 测量)  ──> 性能验收：带 100 个文本节点的 MOC，初次渲染 / 拖动 fps
   │
   ↓
Phase 3 (单源架构)  ──> 编辑流程验收：占位符 / 文本 / 富文本三类编辑无闪烁
   │
   ↓
Phase 4 (UX/重构)   ──> 用户主动验收
```

每个 Phase 独立可上线。Phase 3 改动最大但最值钱。Phase 1 + Phase 2 已经能解决目前肉眼可见的所有 bug，Phase 3 是技术债清理 + 防止未来再踩坑。

## 不做的事（明确划界）

- ❌ 不引入 ResizeObserver 监听编辑器内容（`cy.on('render')` 已经够了）
- ❌ 不切到 SVG 渲染（Cytoscape canvas 性能远好于 SVG，simple-mind-map 节点数远少于我们 MOC）
- ❌ 不上 Web Worker 做测量（DOM 测量必须在主线程）
- ❌ 不动 mermaid 序列化层 / `manualWidthModel` 在 ext metadata 的存储格式
