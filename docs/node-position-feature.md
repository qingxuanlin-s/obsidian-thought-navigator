# 节点位置拖动功能

## 功能概述

在 MOC 索引视图（Index View）的分支图中，节点可以自由拖动，并且位置信息会自动保存到 MOC 文件的思维树标题下。

## 使用方法

### 1. 启用 MOC 模式

在插件设置中：
- 启用 "MOC 模式"
- 设置 "MOC 文件夹路径"（例如：`MOC`）
- 设置 "思维树标题"（默认：`思维树`）

### 2. 创建 MOC 文件

在 MOC 文件夹中创建一个 Markdown 文件，格式如下：

```markdown
# 思维树

- [[笔记1]] `a` - 描述
  - [[笔记2]] `a.1` - 子节点
  - [[笔记3]] `a.2` - 子节点
- [[笔记4]] `b` - 描述
```

### 3. 拖动节点

1. 打开 MOC 文件（在索引视图 Index View 中）
2. 在分支图中，你会看到思维树的可视化
3. 直接拖动节点到你想要的位置
4. 松开鼠标后，位置会自动保存

### 4. 位置信息存储

节点位置会保存在思维树标题下面：

```markdown
# 思维树
---
node_positions:
  "a": { x: 100.50, y: 200.75 }
  "a.1": { x: 300.25, y: 150.00 }
  "b": { x: 100.00, y: 400.00 }
---

- [[笔记1]] `a` - 描述
  - [[笔记2]] `a.1` - 子节点
- [[笔记4]] `b` - 描述
```

## 功能特点

### 索引视图（Index View）- 分支图
- ✅ **可拖动**：节点可以自由拖动
- ✅ **自动保存**：位置信息自动保存到 MOC 文件
- ✅ **持久化**：下次打开时会恢复保存的位置

### 图形视图（Graph View）- 局部图
- ❌ **不可拖动**：节点被锁定，只能查看
- ✅ **显示位置**：会显示保存的位置（如果有）
- ℹ️ **设计目的**：局部视图用于快速查看上下文，不需要编辑布局

## 视图说明

### 索引视图（Index View）
- 打开 MOC 文件时显示
- 显示完整的思维树结构
- 可以拖动节点调整布局
- 位置会保存到 MOC 文件

### 图形视图（Graph View）
- 打开 MOC 树中的某个笔记时显示
- 显示当前笔记的上下文（父节点、兄弟节点、子节点）
- 节点锁定，不可拖动
- 只用于查看关系

## 技术实现

### 数据流

1. **拖动节点** → 触发 `node-position-changed` 事件
2. **事件处理** → 调用 `saveNodePositionToMOC()` 方法
3. **查找标题** → 定位到思维树标题（如 `# 思维树`）
4. **解析位置块** → 读取标题下的 `---` 包裹的位置信息
5. **更新位置** → 添加或更新节点位置
6. **写回文件** → 保存到 MOC 文件

### 位置块格式

位置信息保存在思维树标题下，使用 `---` 分隔符包裹：

```markdown
# 思维树
---
node_positions:
  "节点ID": { x: X坐标, y: Y坐标 }
  ...
---
```

### 关键文件

- `src/renderer/CytoscapeRenderer.ts` - 渲染器，处理拖动事件
- `src/view/indexView.ts` - 索引视图，保存位置到文件
- `src/view/graphView.ts` - 图形视图，禁用拖动
- `src/utils/utils.ts` - 工具函数，解析和转换数据

### 数据结构

```typescript
// ZKNode 接口
interface ZKNode {
    ID: string;
    savedPosition?: { x: number; y: number }; // 保存的位置
    // ... 其他字段
}

// MOC 解析结果
interface MOCParseResult {
    nodes: MOCTreeNode[];
    nodePositions: Record<string, { x: number; y: number }>; // 位置映射
    // ... 其他字段
}
```

## 注意事项

1. **文件格式**：确保 MOC 文件使用正确的格式（带节点 ID 的列表）
2. **节点 ID**：节点 ID 必须用反引号包裹，如 `` `a` ``、`` `a.1` ``
3. **自动布局**：首次打开时，如果没有保存的位置，会使用自动布局
4. **手动编辑**：可以手动编辑位置块中的位置信息
5. **位置块位置**：位置块必须紧跟在思维树标题后面
6. **视图区分**：只有在索引视图中才能拖动节点，图形视图只能查看

## 示例

### 完整的 MOC 文件示例

```markdown
# 思维树
---
node_positions:
  "a": { x: 150.00, y: 100.00 }
  "a.1": { x: 350.00, y: 80.00 }
  "a.2": { x: 350.00, y: 150.00 }
  "b": { x: 150.00, y: 300.00 }
---

- [[量子力学基础]] `a` - 核心概念
  - [[波函数]] `a.1` - 引出
  - [[薛定谔方程]] `a.2` - 引出
- [[相对论]] `b` - 相关理论

`a` --推导--> `a.1`
`a.1` --应用--> `a.2`
```

### 位置块的解析逻辑

1. 查找 `# 思维树` 标题
2. 检查下一行是否是 `---`
3. 如果是，继续查找结束的 `---`
4. 解析中间的位置信息
5. 跳过位置块，继续解析列表内容

## 优势

✅ 位置信息与思维树内容更接近  
✅ 可以在同一个文件中有多个思维树，每个都有自己的位置信息  
✅ 不会污染文件的 frontmatter  
✅ 更符合 Markdown 的语义结构  
✅ 索引视图可编辑，图形视图只读，职责清晰
