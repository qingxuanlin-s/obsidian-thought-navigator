§1目标与非目标

目标（MUST）

  • 任意命名：用户可自由命名顶层 Space 和所有层级子文件夹，无预设关键字
  • 任意嵌套：理论上支持 N 层嵌套，实际建议软限制 10 层
  • 任何文件夹都能升级为"项目"：成为项目后，该文件夹可拥有结构图 + 生长中的文章
  • 与 Obsidian vault 结构共存：不改变 vault 的文件组织，卡片依旧是 markdown
  • 模板可选：首次使用提供 PARA / GTD / 空白等模板的一键创建，但不强制
  • 拖拽重组：像文件管理器一样可以拖拽移动文件夹

非目标（WON'T）

  • 不实现任意复杂的"智能文件夹"（动态查询构建的虚拟文件夹） —— 放 v2
  • 不限制文件夹命名字符（除 OS 非法字符外，都允许包括 emoji）
  • 不把卡片"锁进"文件夹 —— 卡片池始终扁平、跨空间引用
核心前提
文件夹只是组织"项目"和"引用"的容器，不存储卡片本体。卡片住在 vault 的 zk-cards/ 下，是扁平结构；文件夹组织的是项目元数据与文章。

§2数据模型

三层抽象 —— Space（顶层）、Folder（中间任意层）、Project（任何 Folder 可升级）。其中 Project 不是独立类型，而是 Folder 的一个 flag。

MODEL · Space
Space（顶层空间）
用户定义的顶层容器。无预设名字。例如："工作"、"学习"、"生活"、或者按 PARA 分四个。
MODEL · Folder
Folder（中间文件夹）
任意深度嵌套。仅用于组织 Projects 和其他 Folders。本身不含结构图。
MODEL · Project flag
Project（项目标记）
任何 Folder 可设 isProject: true。成为 Project 后可拥有 canvas.json + articles/。

TypeScript 类型定义

TypeScript// src/types/folder.ts

export interface FolderNode {
  id: string;             // UUID, 永不改变（改名时保持）
  name: string;           // 用户看到的名字，可任意改
  path: string;           // 相对 vault 的路径，例如 "zk-spaces/工作/2026 Q2"
  parentId: string | null;   // null = 顶层 Space
  childIds: string[];    // 子文件夹 id（显式存储，用于排序稳定）
  depth: number;          // 0 = Space, >=1 = 子层

  // 扩展能力
  isProject: boolean;     // 是否是"项目"（能拥有 canvas + articles）
  icon?: string;          // 可选 emoji 或 Lucide 图标名
  color?: string;         // 可选颜色（用于树视图上的小点）

  // 排序 / UI 状态
  order: number;          // 同层级排序
  collapsed: boolean;     // UI 折叠状态，持久化

  // 时间戳
  createdAt: number;
  updatedAt: number;
}

export interface ProjectMeta {
  folderId: string;        // 关联的 FolderNode.id
  description?: string;
  status: 'active' | 'paused' | 'done' | 'archived';
  deadline?: number;      // 可选 deadline（不是必须的）
  cardRefs: CardRef[];    // 引用的卡片列表（影子）
  canvas?: CanvasData;
  articleIds: string[];   // 关联的文章文件
}

export interface CardRef {
  cardId: string;          // 指向 zk-cards/ 下的卡片 id
  pos?: { x: number; y: number };
  localNote?: string;     // 项目内注释（不影响卡片本体）
  addedAt: number;
}
为什么 path 和 id 都存
id 是稳定的（重命名/移动时不变），所有引用用 id 关联。path 是当前文件系统位置，用户可见、方便 reveal in vault。两者通过 PathIndex 维护映射，任何改名/移动要同步更新。

为什么每个文件夹都放 _folder.json
便于 Obsidian 原生文件操作（用户在资源管理器直接移动/改名文件夹）也能被正确识别 —— 插件只要看到 _folder.json 就知道这是一个 ZK 空间/文件夹节点。id 保存在文件里，移动不丢身份。

§4索引层设计

在插件加载时扫描所有 _folder.json，构建内存中的双向树，订阅 vault 事件实时同步。

TypeScript// src/index/VaultIndex.ts

export class VaultIndex {
  private nodes = new Map<string, FolderNode>();          // id → node
  private pathToId = new Map<string, string>();          // path → id
  private rootIds: string[] = [];                       // 顶层 Space ids
  private emitter = new EventEmitter();

  async bootstrap(vault: Vault): Promise<void> {
    // 1. 扫描 zk-spaces/ 下所有 _folder.json
    const files = await findFolderFiles(vault, 'zk-spaces');
    for (const f of files) {
      const node = JSON.parse(await vault.read(f));
      this.nodes.set(node.id, { ...node, path: dirname(f.path) });
      this.pathToId.set(dirname(f.path), node.id);
    }
    // 2. 解析 parent/child 关系
    this.rebuildTree();
    // 3. 订阅 vault 事件
    this.subscribeVaultEvents(vault);
  }

  // 订阅 vault 事件，实时维护索引
  private subscribeVaultEvents(vault: Vault) {
    vault.on('rename', (file, oldPath) => {
      if (file.path.endsWith('_folder.json')) this.handleRename(file, oldPath);
    });
    vault.on('delete', (file) => {
      if (file.path.endsWith('_folder.json')) this.handleDelete(file);
    });
    vault.on('create', (file) => {
      if (file.path.endsWith('_folder.json')) this.handleCreate(file);
    });
  }

  // Public API
  getNode(id: string): FolderNode | undefined { return this.nodes.get(id); }
  getChildren(id: string): FolderNode[] { /* ... */ }
  getPath(id: string): string[] { // 返回从根到该节点的 id 链 */ }
  getRoots(): FolderNode[] { return this.rootIds.map(id => this.nodes.get(id)!); }

  on(event: 'change', cb: () => void) { this.emitter.on(event, cb); }
}
关键不变式
索引中任意 FolderNode 必须满足：① 存在对应的 _folder.json 文件；② path 与文件实际位置一致；③ parentId 对应的节点一定存在（或为 null）。任何 vault 事件都要通过 事务式修改 保证不变式。

§5服务层 API

UI 层不直接操作文件或索引，统一通过 SpaceService —— 把"业务动作"封装成原子操作，内部处理文件创建、索引更新、事件广播。

TypeScript// src/services/SpaceService.ts

export class SpaceService {
  constructor(
    private vault: Vault,
    private index: VaultIndex,
  ) {}

  // 创建顶层 Space
  async createSpace(name: string, opts?: { icon?: string; color?: string }): Promise<FolderNode> {
    assertValidName(name);
    assertNoConflict('zk-spaces/' + name);
    const node: FolderNode = {
      id: genId('flt'),
      name, parentId: null, childIds: [], depth: 0,
      isProject: false, order: this.index.getRoots().length,
      collapsed: false, createdAt: Date.now(), updatedAt: Date.now(),
      ...opts,
    };
    await this.vault.createFolder(`zk-spaces/${name}`);
    await this.writeFolderMeta(node);
    return node;
  }

  // 在任意父节点下创建子文件夹
  async createFolder(parentId: string, name: string): Promise<FolderNode> { /* ... */ }

  // 将任意文件夹升级为项目
  async promoteToProject(folderId: string): Promise<void> {
    const node = this.index.getNode(folderId);
    if (!node || node.isProject) return;
    node.isProject = true;
    await this.writeFolderMeta(node);
    await this.writeProjectMeta({ folderId, status: 'active', cardRefs: [], articleIds: [] });
    await this.vault.createFolder(`${node.path}/articles`);
  }

  // 重命名（保持 id 不变）
  async rename(folderId: string, newName: string): Promise<void> { /* ... */ }

  // 移动（改变父节点）
  async move(folderId: string, newParentId: string | null, beforeId?: string): Promise<void> { /* ... */ }

  // 删除（两段式：项目内有引用时提醒）
  async delete(folderId: string, opts: { keepArticles?: boolean }): Promise<void> { /* ... */ }

  // 按模板批量创建
  async applyTemplate(tmpl: SpaceTemplate): Promise<FolderNode[]> { /* ... */ }
}

关键算法：move 的原子性

陷阱
把 /工作/Q2/JVM 移到 /学习 下时，必须原子完成：① 文件系统 rename 整个目录；② 更新所有子孙节点的 path；③ 更新 parentId；④ 索引 pathToId 全部刷新。任一步失败要回滚。

§7交互细节

7.1 新建 —— 永远"所见即所得"

点击 + 按钮或按 ⌘N：

  • 在当前选中节点下 原位展开 一个输入框（不弹 modal）
  • 回车确认，Esc 取消
  • 名字有冲突时实时显示红色下划线 + 提示
  • 支持用 / 分隔一次性创建多层：输入 2026 Q3/周报/04.20 会自动建三层

7.2 重命名

  • 双击节点名或 F2 进入原位编辑
  • 同步改 _folder.json.name 和实际文件夹名
  • ID 不变，所有引用仍然有效

7.3 拖拽

最复杂的交互。三种放下位置必须视觉可区分：

放到节点上方（加横线）
= 作为兄弟节点插入上方
放到节点下方（加横线）
= 作为兄弟节点插入下方
放到节点中间（整行高亮）
= 作为子节点移入。如果节点是 .md 文件或叶子项目，禁止此状态（拒绝 drop）。

DANGEROUS

§9边界情况与性能

9.1 同名冲突

  • 同层级禁止同名。保存时检测。
  • 跨层级允许同名（"工作/周报" 和 "生活/周报" 共存）。

9.2 外部改动 vault

  • 用户在 Obsidian 文件管理器里直接删除/改名 —— watch vault events，自动同步索引。
  • 用户外部（Finder）移动了 _folder.json —— 下次 bootstrap 扫描时根据其路径重建 parent 关系。
  • 丢失的 _folder.json —— 树里该节点消失，但下级 _folder.json 还在时，将它们标记为"孤儿"并在 UI 顶部显示"修复"入口。

9.3 性能

规模策略
≤ 500 节点全量加载到内存，无需优化
500-5000树视图用虚拟滚动（react-virtual）
> 5000索引 JSON 快照写入 .zk/index.json，启动时直接读快照 + 增量校验；考虑分层懒加载 _folder.json

9.4 循环引用

move 操作时必须检查：目标 parent 不能是源节点的子孙。否则拒绝并提示。

9.5 跨空间移动项目的卡片引用

好消息
卡片引用用的是 cardId，不依赖项目的 path。把一个项目从"工作/Q2"移到"学习/课程"，所有卡片引用保持有效。这就是 id + path 分离的最大红利。

§附录 · 关键决策对照

决策选择理由
Project 是独立类型还是 flagFolder 的 flag允许任何文件夹升级/降级，最大灵活性
id 存哪里_folder.json 文件内跟随文件夹移动/改名而不丢失
卡片存放位置zk-cards/ 扁平保证跨空间引用不受文件夹结构影响
文章存放位置各 Project 文件夹下 articles/文章属于项目、跟着项目走；与卡片分开
PARA 是否内置作为可选模板尊重用户自由，不做架构性绑定
外部文件系统改动监听并同步与 Obsidian 的开放性原则一致
这份文档的适用范围：仅覆盖"可自定义文件夹分类"这一模块。与之相关但独立的模块 —— 卡片池索引、结构图画布、跨项目引用 UI、AI 联想推荐 —— 各有独立文档。实现时按此顺序：文件夹 → 卡片池 → 结构图 → 引用 UI → 推荐。

写完这个模块的验收：用户能自由创建任意命名空间与嵌套文件夹，任意文件夹可升降级为项目，项目可存放结构图和文章，所有改动通过 UI 或文件管理器都能正确同步。
