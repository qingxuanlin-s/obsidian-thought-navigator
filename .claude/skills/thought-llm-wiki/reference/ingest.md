# ingest —— 摄取一篇新源(人在环中)

llm-wiki 的核心写入。本文件决定**提议什么**,MOC 的草稿注入/落地交给 [`thought-navigator-map`](../../thought-navigator-map/SKILL.md)。
前置(定位 wiki + 读 schema)见 [`../SKILL.md`](../SKILL.md)。

## 工作流(逐步,和用户确认)

1. **读源**:读 `raw/` 里的新源,先和用户过一遍 takeaways,问要强调什么。
2. **写摘要**:`wiki/摘要-<标题>.md`,frontmatter 标 `sources`。一源一页,只浓缩、不跨源。
3. **回头更新实体/概念页(复利所在,不止写新页)**:
   - **提升判断(通用两档,满足其一才建独立页)**:① **复现** —— 在 ≥2 篇源出现(零判断);② **首要类型 + 实质** —— 是该库 schema 声明的「首要实体类型」实例,**且**源里对它有归属内容(角色/动作/属性,非单纯点名)。其余留摘要、等复现。**判断依"类型+实质"而非"重不重要"**,避免名气偏见。〔此规则是对 llm-wiki 空白的通用补充,非原文〕
   - **冲突不覆盖**:新旧打架 → `⚠️ 矛盾` 块并列两来源(典型:兵力"号称 vs 实则")。
   - 概念被新源强化/推翻 → 改概念页。
   - Zettelkasten 变体:若 schema 规定永久笔记由用户写,则**只提示该更新哪几页**,不代笔。
4. **重审综合 `wiki/综合.md`**:新源是否动摇当前论点?动摇 → **升版本重写**(v1→v2),保留旧版备注。判断标明是推断。
5. **维护概述 `wiki/概述.md`(全局入口,别漏)**:库空则创建,否则更新 —— 刷新覆盖范围、"从哪读起"的指引、hub/孤儿、空白待补方向。概述是 overview,**只指路不堆内容**(详情在各页里)。
6. **更新 `index.md`**;`log.md` 追加 `## [YYYY-MM-DD] ingest | <标题>`,列出"这一篇动了哪几个旧页"。
7. **关系入图**:见下。

## 入图(两张 MOC,双图同步)

MOC 层是**两张图**(范式详见 [`moc-layer.md`](moc-layer.md)):`综合.moc.md`=目录树,`关系图.moc.md`=关系网。两张都**只画实体/概念,raw/摘要不入图**(溯源走 `sources:`)。

ingest 一篇新源,**两张都更新**:

- **综合树**:新实体→「实体」支、新概念→「概念」支、新关系页/对比→「关系」支。机械的(源里点名的)直接 `addNodes` 落盘。
- **关系图**:新实体加节点;实体间关系连边 —— 父子层级用节点 `relationText` 带标签、跨链用 `reverseRelations`;有**时序的事件**在标签前加 `①②③`(叠时间线,常设关系留空号)。
- **创造性关系**("说不清但好像有关")→ **走草稿审批**:节点 `addDraftNodes`、边 `addDraftRelations`,用户画布拍板(见 thought-navigator-map 的 [`drafts.md`](../../thought-navigator-map/reference/drafts.md) / [`relations.md`](../../thought-navigator-map/reference/relations.md))。
- **单源/单实体阶段关系图会退化成几个点,正常** —— 料够了再连,别硬画。

> 重排/分组用 `deleteNode` + `addNodes` 局部重接,别 `createMOC overwrite`(整树 ID 漂移)。注入草稿后告诉用户去画布「确认落地 / 丢弃」。

## 收尾

向用户汇报:新建/更新了哪些页、标了哪些矛盾、综合是否升版、画布上有几个待审草稿。等用户拍板再结束。
