# MOC 层:两张图,各司其职

llm-wiki 的可视化层用**两张 MOC**,别混成一张(混了就是"目录"和"关系网"互相打架,同级错乱)。
两张都守一条铁律:**只画实体/概念,raw 与摘要不入图** —— 溯源走各页 `sources:` frontmatter,不画成边。
(`.moc.md` 是纯 JSON 文件,可直接读写。)

## 1. `综合.moc.md` —— 目录树(catalog)

- **结构**:`综合(根) → {实体, 概念, 关系} 三类内容桶 → 各页(file 节点)`
- **布局**:`auto`(层级)
- **无 reverseRelations** —— 目录要干净,横向关系全搬到关系图
- **「关系」支**装关系页 / 对比页(如 `比较-官渡vs赤壁`),和 实体/概念 齐整为三类内容
- **职责**:分类导航入口

## 2. `关系图.moc.md` —— 关系网(network)

- **根 = 最核心实体**(protagonist / hub 的**真实 file 节点**,**不要空壳容器节点**——它既是真东西又天然是中心)
- **父子边 = 有意义的层级**(hub → 相关实体;可再下钻,如 `火攻 → 执行者黄盖`)。
  给节点写 `relationText`,它就是**父→子边的标签**(`GraphDataBuilder` 第 66 行:`label: node.relationText`)→ 实线父子边也能带字。
- **跨链 = reverseRelations**(实体间非层级关联,虚线带标签,如 `黄盖→周瑜:部将`)
- **事件序 = ①②③ 前缀**:有时间/因果顺序的边,在 `relationText` 前加序号,给关系网叠一条**时间线**(空间维 + 时间维同图)。常设关系(非事件)留空号。
- **布局**:`free`(自由定位,节点**要给显式坐标** `nodePositions`)
- **职责**:看关系网 + 事件流

## 双图同步(ingest 时两张都要动)

每 ingest 一篇新源,新实体/概念/关系**两张图都更新**:

| 改动 | 综合树(目录) | 关系图(网络) |
|---|---|---|
| 新实体 | 挂「实体」支 | 加节点 + 连相关边 |
| 新概念 | 挂「概念」支 | 加节点 + 连边 |
| 新关系页 / 对比 | 挂「关系」支 | 连对应的边(页本身在综合) |
| 新发现的关联 | —— | 加横向边(创造性的走草稿审批) |
| 有时序的事件 | —— | 边 `relationText` 加 ①②③ |

> 同一实体一note多图,靠 multiverse,**不复制笔记**。

## 怎么建 / 改(API)

- **综合树节点**:`addNodes`(直接,auto)/ `addDraftNodes`(草稿)。
- **关系图(自由布局要坐标)**:`addNodes` **不收坐标**,两条路 ——
  1. `addDraftNodes`(带 `position`)→ 审批落地;
  2. 直接写 `.moc.md` JSON(`nodePositions` + 节点 `relationText` + `reverseRelations`),写完触发刷新。
- **横向边**:`addRelations`(直接)/ `addDraftRelations`(草稿,**默认**;创造性关系走它,和草稿节点共用审批操作条)。
- **重排 / 分组**:`deleteNode` + `addNodes` **局部**重接,**别** `createMOC overwrite`(整树 ID 漂移、关系全得重连)。

## 一致性铁律(易漏,务必核对)

- **file 节点必须先有页**:往任一 MOC 加 `kind:'file'` 节点前,先确保对应 `.md` 页**已存在**,否则就是**断链**(节点指向不存在的笔记)。顺序永远是 **先写页 → 再加 MOC 节点**。
- **直接写 `.moc.md` JSON / 重排 / 复制库时最易漏**(加了节点、没建页)。改完**逐一核对**每个 file 节点都有对应 `.md`(可 `ls wiki/` 比对)。
- **关系页成边需两端是实体**:`比较/关系` 页要画成**关系图的边**,前提是它两个端点都是图中实体;端点若是摘要或不存在的节点,该关系只能作为**页**待在综合「关系」支,**画不成边**(例:`比较-官渡vs赤壁` 的端点是两场战役,只有把战役建成「战役」实体后才能连边)。
