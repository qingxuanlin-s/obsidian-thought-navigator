# lint —— 库的健康体检(派子代理扫 + 收报告)

体检要**读全库**:机械的大量读取,过程不需用户插手,只有结果要给用户 —— 这是 agent 的活。
本路只做"派活 + 收报告 + 陪用户拍板",扫描交给 `wiki-lint` 子代理。

## 工作流

1. **前置**:定位 wiki 根目录(含 `index.md`),拿到绝对路径。
2. **派出子代理**:用 Agent 工具 spawn,`subagent_type: wiki-lint`,把 wiki 根目录绝对路径告诉它,让它**只读扫描、回结构化报告**。
   - 为什么用 agent:全库读取量大、要隔离上下文、跑完才需要你 —— 别在主对话自己硬扫。
3. **收报告后分组呈现**:矛盾 / 过期 / 孤儿页 / 缺页的概念 / 缺失交叉引用 / index 不同步 / 源缺口,按高/中/低优先级。
4. **逐条陪用户拍板** —— lint 只**提建议**,不自动改库。用户点头的修复项,转交 [`ingest.md`](ingest.md) / [`query.md`](query.md) 或直接编辑执行;创造性的新关系仍走草稿。
5. `log.md` 追加 `## [YYYY-MM-DD] lint | <一句话结论>`。

> 子代理只读不写:它产报告,改动永远回到主对话、经用户同意。报告太长就让它先报高优先级。
